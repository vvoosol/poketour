# 3단계: 모험 안내·목표·수집·보관함

이 문서의 전투·출현 측정은 당시 규칙 기준이다. 2026-10-21 이후 현재 규칙은 [지도 전투·공원 출현·저장](FIELD_COMBAT.md)을 따른다.

## 적용 내용

기존 세로 9:20·가로 20:9 고정 배치와 도트 UI를 유지한다. 지도 위에 안내창을 추가하지 않고 메뉴 → ‘모험 안내 · 목표’에서 스타팅·경로 선택·시설 도착·야생 접근·저장 백업을 설명한다. 출현 주기와 확률은 실제 게임 설정을 읽어 안내한다.

| 목표 | 완료 조건 | 1회 보상 |
| --- | --- | --- |
| 첫 목적지 도착 | 이동 완료 1회 | 200원 |
| 첫 전투 승리 | 승리 1회 | 상처약 2개 |
| 첫 야생 포획 | 포획 1회 | 몬스터볼 5개 |
| 다섯 종의 동료 | 팀·보관함에 서로 다른 5종 보유 | 슈퍼볼 3개 |
| 열 종의 동료 | 서로 다른 10종 보유 | 500원 |
| 첫 체육관 배지 | 배지 1개 | 좋은상처약 2개 |

진행도는 실제 이동·승리·포획 기록과 보유 종 수로 계산한다. 중복 개체는 수집 종 수를 늘리지 않는다. 보상은 엔진이 정한 값만 지급하며 저장의 adventureClaims에 수령 여부를 남긴다. 같은 보상은 새로고침·동시 탭·파일 복원 후에도 다시 받을 수 없다. 이전 저장은 빈 수령 목록으로 호환된다. 이전 백업으로 진행도 전체를 되돌리는 것까지 서버 없이 차단한다고 보장하지는 않는다.

탐험 팀 → 보관함에서 한글·영문 이름과 도감 번호를 검색한다. 전체·색이 다른 포켓몬·전투 가능·기절 필터와 최근 포획·레벨·도감 번호·이름 정렬을 제공한다. 24마리씩 더 보며 검색/정렬은 저장 배열과 개체 UID를 바꾸지 않는다. 자동 저장이 실행되어도 검색 입력창과 검색어를 유지한다.

## 전투·출현 측정과 보상 조정

`npm run measure:balance`로 고정 seed의 전투 72회(스타팅 3종 × 빠른 처치/포획 우선 × 12회), 첫 가까운 야생 출현 200회를 측정한다. 결과는 `docs/BALANCE_REPORT.json`에 저장한다. 전투는 Lv.5 스타팅 대 Lv.5 꼬렛, 자동 회복·위험 이탈 없이 종료까지 측정하는 조건이다. 실제 휴대폰 플레이나 전체 종·기술의 밸런스를 대표하지 않는다.

| 스타팅 | 빠른 처치 중간 종료 시간 | 포획 우선 중간 종료 시간 |
| --- | --- | --- |
| 머드나기 | 552초 | 348초 |
| 샤프니아 | 30초 | 24초 |
| 찌리비 | 1,794초 | 1,116초 |

빠른 처치 시 찌리비는 이 조건에서 12회 모두 전멸로 종료됐다. 가까운 야생의 첫 출현은 중간 600초·95백분위 1,800초였다. 스타팅·기술·특성·HP 배율로 인한 편차가 커서 기존 공식과 HP 100배, 6초 행동 간격, 10분/30분 출현 주기는 변경하지 않았다. 이번 조정은 초반에 첫 도착 보상을 먼저 얻고, 이후 수집으로 볼·회복 도구를 보충하는 1회성 보상에 한정한다. 전투 공식·출현 빈도의 추가 조정은 실제 플레이 확인 후 진행한다.

## 검증 범위

빌드와 전체 자동 검사에 실제 엔진의 이동 완료·보상 자격·중복 수령 거절·이전 저장 호환성, IndexedDB 동시 보상 요청·복원, 모의 DOM 검색·필터·나눠 보기·검색창 유지 검사를 추가했다. 실제 브라우저 화면·휴대폰 GPS·터치 확인은 완료하지 않았다. GitHub 업로드는 사용자가 직접 한다.
