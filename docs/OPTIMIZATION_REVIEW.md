# 정리 결과와 다음 개발 우선순위

## 이번에 적용한 정리

- 이전 poketour-play 전용 게시 스크립트를 제거했다. 배포 명령과 개발 안내는 현재 poketour 저장소의 Pages Actions를 가리킨다.
- assets는 dist/client와 정확히 일치하도록 다시 생성한다. 구형 파일/하위 폴더가 다음 배포에 남지 않으며 루트 index는 보존한다. 자산 루트가 심볼릭 링크이면 중단한다.
- 중복 팀 아이콘은 기존 볼 아이콘을 공유한다. 빌드에만 쓰는 file-runtime.mjs 원본은 실행 파일로 복사하지 않는다. 파일 직접 실행용 번들 자체는 유지하고 압축한다.
- 읽지 않는 lastMapAttack/visualOffset과 임시 auto 변수를 제거했다. 전투 재생 타이머가 그리는 동안 유휴 지도 RAF는 동일한 표식/장면 갱신을 반복하지 않는다. 전투 종료 뒤 유휴 모션은 재개한다.
- 저장 버전/UID/CAS/중복 요청/보상/전투 판정과 두 고정 화면 배치는 유지했다. CSV 원본·이미지·제작자 고지·엔진 회귀 검사·현재 미리보기는 필요하므로 보존했다.

## 측정과 검증

정리 전 실행 자산은 1,144개/19,411,988바이트, 정리 후는 1,142개/19,376,238바이트다. 전체 자산 기준 약 0.18% 감소다. 파일 직접 실행 번들은 8,456,903→8,422,721바이트로 줄었다. 이는 파일 크기 측정이며 실제 통신 압축률·로딩 시간·휴대폰 FPS 향상 측정은 아니다. HTTPS에서는 큰 file-mode.js를 원래부터 내려받지 않으므로 이를 웹 첫 화면 로딩 개선으로 설명하지 않는다.

빌드와 전체 npm test가 통과했다. 구형 산출물의 제거, 루트 index 보존, 업로드 파일 해시, 파일 직접 실행, 지도 전투 중 중복 호출 차단과 종료 뒤 재개, 기존 저장/백업/전투 검사를 포함한다. 이번 정리는 실제 브라우저/휴대폰 시각 검증을 추가로 수행하지 않았다.

## 다음 개발 제안

1. **휴대폰에서 기본 플레이 완주 검증.** Android Chrome과 iPhone Safari에서 시작→이동→도착 아이콘→활동→자동/수동 전투→포획→기절/회복→백업/복원을 한 번씩 완주한다. 방향 전환과 앱 복귀도 포함한다. 완료 기준은 막히는 흐름·화면 잘림·진행도 손실이 없는 것이다.
2. **테스트 밸런스와 실제 플레이 설정 분리.** 현재 이동 10배·자동 HP 10배·생성 버튼은 테스트용이다. 개발/플레이 프로필과 현재 설정 표시를 만들고, 실제 조우 간격·첫 포획까지 걸린 시간·전투 길이·회복 빈도를 측정해 조정한다. 기존 저장의 모드를 몰래 바꾸지 않는다.
3. **전투 피드백과 콘텐츠 완성.** 포획 결과 유지에 이어 기절 시 회복 장소 안내, 효과/상성/상태 이상, 전투 보상과 성장 결과를 일관되게 표시한다. 미확보 뒷모습·공격 모션을 확장한다. 기존 6개 목표 다음에 공원 탐사/첫 배지 등 짧은 연속 목표를 연결한다.
4. **큰 데이터 처리와 저장 비용 실측.** 6.46MB 보행 그래프의 첫 다운로드·파싱·경로 계산을 분리 측정한다. 병목이 확인되면 캐시 버전 관리와 Web Worker 경로 계산을 적용한다. 1초 정산마다 IndexedDB 기록이 늘어나는 비용도 장시간 플레이에서 측정한다. 빈도 변경은 저장 신뢰성 검사와 함께 한다.
5. **PWA 설치와 업데이트를 검증한 뒤 앱 포장.** 홈 화면 설치, 저장 백업 안내, 구버전 캐시 정리와 업데이트 알림부터 만든다. 지도 타일은 외부 네트워크 의존이 있으므로 완전 오프라인 지도를 약속하지 않는다. 그 뒤 Android/iOS 권한·앱 복귀·파일 복원을 실기 검증한다.

기술 참고: [MDN PWA 캐싱](https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Caching), [web.dev 입력 반응 최적화](https://web.dev/articles/optimize-inp). 제안은 현재 코드 분석을 바탕으로 하며 위 후속 기능을 이번에 구현했다는 뜻은 아니다.
