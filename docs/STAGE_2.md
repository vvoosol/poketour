# 2단계: 로그인 없는 브라우저 실행

2026-10-20 기준 코드 구현과 자동 검증을 완료했다. 사용자 GitHub 업로드와 실제 휴대폰 검증은 별도이며 완료했다고 간주하지 않는다.

## 실행과 저장

최상위 index.html과 assets 전체로 실행한다. 로그인이나 API 서버가 필요하지 않다. 이동·전투·포획·성장·시설 이용은 기존 공유 엔진을 재사용하며 기본 저장은 브라우저 IndexedDB다. 서버 시각이 아닌 기기 시각으로 정산한다. 파일 실행·localhost·GitHub Pages는 저장 영역이 다르므로 백업 파일로 옮긴다.

## 저장 충돌과 재접속

상태와 사건 기록을 같은 트랜잭션으로 저장한다. 서로 다른 탭의 변경은 revision 비교로 충돌 처리하고 최신 상태를 반환한다. 같은 requestId의 동시 요청은 한 번만 저장하고 다른 요청에는 재처리 결과를 반환한다. 최근 40개 requestId를 기억한다. 이동 중 재접속해도 출발 정보와 진행도를 보존하고, 같은 시각의 정산·재전송으로 보상을 중복 지급하지 않는다.

## 백업·복원

메뉴의 ‘이 브라우저의 저장’에서 파일을 내보내거나 선택한 파일을 명시적으로 복원한다. 개체 UID·레벨·능력치·HP·기술 PP와 기록 번호를 검증한다. 검증 실패 시 기존 상태와 보관 기록을 변경하지 않는다. 이전 저장 version 3/4의 UID·HP·재화를 보존하는 migration을 검사한다. 복원 후 화면에 캐시된 이전 모험 기록과 페이지 위치를 초기화한다. 파일을 연속 선택해도 늦게 읽힌 이전 파일이 새 선택을 덮지 않는다.

## 자동 검증과 실기 확인

`songpa-site/`에서 `npm run build` 후 `npm test`를 실행한다. 기존 엔진·지리·시설·전투·성장·저장 검사를 유지하고 IndexedDB 재열기·다중 탭 충돌·동시 중복 요청·이동 재개·백업 복원 및 손상 파일 거절을 검사한다. IndexedDB와 화면 검사는 fake-indexeddb·모의 DOM 기반으로 실제 휴대폰 동작 검증을 대신하지 않는다.

업로드 후에는 실제 휴대폰에서 시작 → 이동 중 닫기/재열기 → 가방·동행 확인 → 백업 → 다른 브라우저에 복원 순서로 확인해야 한다. 외부 지도 타일과 상세 경계 조회에는 인터넷이 필요하다. 브라우저 데이터를 지우면 저장이 사라질 수 있으며 기기 간 자동 동기화는 제공하지 않는다.

지도 출처는 지도 위에서 제거하고 메뉴 마지막의 작은 링크로 옮겼다. 게임 메뉴에 표기할 수 있다는 [OSMF 게임·시뮬레이션 출처 기준](https://osmfoundation.org/wiki/Licence/Attribution_Guidelines#Computer_games_and_simulations)을 참고했다.
